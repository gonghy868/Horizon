## [波兰字母消失之谜](https://aresluna.org/the-curious-case-of-the-disappearing-polish-s/) ⭐️ 7.0/10

一篇 2015 年的文章揭示了波兰语变音字母（如'ś'）在网页应用中消失的原因：浏览器将 AltGr 组合键解释为键盘快捷键而非字符输入。文章解释了根本原因，并提供了使用 keydown 事件处理的 JavaScript 修复方法。 此问题影响数百万波兰语用户，并凸显了网页应用中国际化键盘输入的普遍问题。理解和修复它有助于改善非英语用户的可访问性和用户体验。 修复方法涉及拦截 keydown 事件并检查 AltGr 修饰键（例如 event.altKey && event.code），以允许波兰字符通过。但该解决方案仅适用于 Windows，无法处理所有情况，例如 macOS 上的 Alt+Cmd+S。

hackernews · HN RSS · 6月28日 12:44 · [社区讨论](https://news.ycombinator.com/item?id=48706814)

**背景**: 波兰语使用拉丁字母，并包含九个变音字符（ą, ć, ę, ł, ń, ó, ś, ź, ż）。在波兰语键盘上，这些字符通过 AltGr 键（右 Alt）与基础字母组合输入。网页浏览器常将 AltGr 组合拦截为键盘快捷键，从而阻止字符输入到输入框中。

## [OpenAI Codex 敏感文件泄露问题仍未解决](https://github.com/openai/codex/issues/2847) ⭐️ 7.0/10

GitHub 上的一个议题（openai/codex#2847）仍然开放，指出 OpenAI Codex 可能通过工具输出（如 grep）泄露敏感文件（如 .env），社区成员建议采用沙箱和选择性加入访问作为解决方案。 这一持续存在的安全问题影响所有使用 Codex 等 AI 编码助手的用户，因为敏感数据泄露可能导致凭证泄露或数据泄露，而讨论内容也影响着行业处理代理安全的方式。 该议题指出，即使没有直接文件访问权限，Codex 也可能通过 'rg foo' 等输出匹配结果的命令间接泄露文件内容；社区评论建议使用操作系统级权限（chmod）或容器化，而不是依赖工具本身。

hackernews · HN RSS · 6月28日 12:27 · [社区讨论](https://news.ycombinator.com/item?id=48706714)

**背景**: OpenAI Codex 是一种 AI 编码代理，可以执行命令并访问用户环境中的文件。像 .env 这样的敏感文件通常包含 API 密钥和机密信息。泄露问题之所以出现，是因为 Codex 可能无意中上传包含敏感数据的工具输出，从而给未正确限制访问权限的用户带来安全风险。

## [公共 DNS 解析器选择指南](https://evilbit.de/dns-resolver-guide.html) ⭐️ 6.0/10
